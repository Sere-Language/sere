# gl — OpenGL

An OpenGL binding for Sere, backed by the runtime's window and context layer
(`runtime/sere_gl.c`). It exposes the API the way the specification does: one
function per entry point, `GL_*` names for the enumerants, and small classes for
the objects that need a lifetime.

```sere
import gl

def main() -> i32:
    window: gl.Window = gl.Window("triangle", 640, 360)
    if not window.is_open():
        print("no display available")
        return 1

    window.make_current()
    gl.default_depth_state()

    while window.is_open():
        window.poll()
        if window.should_close() or window.key_pressed(gl.KEY_ESCAPE):
            window.destroy()

        gl.viewport(0, 0, window.framebuffer_width(), window.framebuffer_height())
        gl.clear_color(0.08, 0.09, 0.12, 1.0)
        gl.clear(gl.GL_COLOR_BUFFER_BIT)

        gl.begin(gl.GL_TRIANGLES)
        gl.color3f(1.0, 0.35, 0.3)
        gl.vertex2f(0.0, 0.7)
        gl.color3f(0.3, 1.0, 0.5)
        gl.vertex2f(-0.7, -0.6)
        gl.color3f(0.3, 0.5, 1.0)
        gl.vertex2f(0.7, -0.6)
        gl.end()

        window.swap()

    return 0
```

Build and run it like any other program:

```
sere build && bin/app.exe
```

## What is here

| Module | Contents |
| --- | --- |
| `gl.constants` | `GL_*` enumerants, `WINDOW_*` flag bits, `CURSOR_*`, `MOUSE_*`, `MOD_*`, and the `KEY_*` virtual-key codes. Generated by `scripts/gen-gl-constants.py`. |
| `gl.types` | `GLenum`, `GLbitfield`, `GLuint`, `GLint`, `GLsizei`, `GLfloat`, and the list aliases used in signatures. |
| `gl.info` | Driver identity, extension list, display size, and the numeric query getters. |
| `gl.errors` | `take_error()`, `error_name()`, `require()`, and the draining helpers. |
| `gl.state` | Clear, viewport, blending, depth and stencil, culling, rasterisation, pixel store, hints, and synchronisation. |
| `gl.immediate` | `begin`/`end` geometry with the triangle, rectangle, line, and circle helpers. |
| `gl.shaders` | `Shader` and `Program`, including uniform setters and the GLSL logs. |
| `gl.buffers` | `Buffer` and `VertexArray`, attribute layouts, and the draw calls. |
| `gl.textures` | `Texture`, filtering and wrapping helpers, and image upload. |
| `gl.framebuffer` | `Framebuffer`, `Renderbuffer`, blitting, and pixel readback. |
| `gl.window` | `Window`: creation, the frame loop, input, timing, and the clipboard. |
| `gl.transform` | Projections, views, `Camera`, `Transform`, matrix uniform uploads, screen space, picking. |

`gl/__init__.sere` is a barrel that imports every part by name and re-exports it,
so `import gl` is the only import a program needs. It is generated by
`scripts/gen-gl-init.py`; add a part to the list at the top of that script and
regenerate after changing a module's public names.

## The math layer

`gl.transform` is the bridge between `stdlib/matrix.sere` and the driver. A camera
and a transform are enough for most scenes:

```sere
import gl
import matrix
import vec

VERTEX: str = """#version 120
attribute vec3 position;
uniform mat4 mvp;
void main() {
    gl_Position = mvp * vec4(position, 1.0);
}
"""

FRAGMENT: str = """#version 120
void main() {
    gl_FragColor = vec4(1.0, 0.6, 0.3, 1.0);
}
"""

def main() -> i32:
    window: gl.Window = gl.Window("scene", 640, 400)
    if not window.is_open():
        return 1
    window.make_current()

    program: gl.Program = gl.build(VERTEX, FRAGMENT)
    if not program.ok():
        print(program.log)
        window.destroy()
        return 1
    program.use()

    camera: gl.Camera = gl.orbit_camera(gl.vec3(0.0, 0.0, 0.0), 30.0, 20.0, 8.0)
    camera.set_aspect_ratio(gl.aspect_of_window(window))
    camera.upload(program, "view", "projection")

    model: gl.Transform = gl.Transform()
    model.turn(0.0, 0.4 * window.dt(), 0.0)
    gl.set_matrix4(program, "model", model.matrix())
    camera.upload_mvp(program, "mvp", model.matrix())

    gl.apply_frame(camera, window)
    gl.clear_color(0.1, 0.1, 0.14, 1.0)
    gl.clear(gl.GL_COLOR_BUFFER_BIT + gl.GL_DEPTH_BUFFER_BIT)
    window.swap()

    program.destroy()
    window.destroy()
    return 0
```

`Camera.view()`, `.projection()`, and `.view_projection()` are ordinary
`matrix.Mat4` values, so they compose with anything else in `matrix`, and
`gl.project_to_screen`/`Camera.ray` close the loop between world space and the
pixels you drew into.

A complete lit cube, an orbit camera driven by the mouse, a sprite overlay in
pixel space, and the picking helper are all in
[`docs/gl.md`](../../docs/gl.md#matrices-and-3d-math).

## Conventions

- **Enumerants are `u32`**, because the runtime passes them to the driver as
  `uint32_t`. Counts, sizes, levels, and locations are `i32`, byte offsets are
  `i64`, and scalars are `f64` (the runtime narrows them to `float`).
- **Buffers and images take Sere lists.** `buffer_data_f64` reads a `list[f64]`,
  `buffer_data_i32` a `list[i32]`, and the texture uploads a `list[byte]`. The
  runtime reads each element's width from the list itself, and the data is
  copied at call time, so the list may go out of scope afterwards.
- **Boolean-valued driver calls return `bool`.** Wrappers around calls that
  report an integer flag map it for you: `is_enabled`, `key_pressed`,
  `complete`, `link`, `compile`.
- **Errors are not exceptions.** A failing call leaves a flag queued;
  `gl.error("draw")` returns a message for it and `gl.require("draw")` raises
  `RuntimeError`. Nothing else in the package raises.
- **No context, no work.** Every function is safe to call before a window is
  made current: the runtime guards the driver pointers, so object creation
  returns 0 and queries return zeroes. Check `window.is_open()` after creating a
  window, and `gl.available()` to tell whether a driver loaded at all.
- **Matrices have two storage orders.** `matrix` is row-major and OpenGL reads a
  `mat4` uniform column-major (the runtime passes `transpose = 0`), so a
  `matrix.Mat4` goes to the driver through `gl.set_matrix4(program, name, m)` or
  `gl.matrix4_data(m)`, never as `m.data`. The two orders describe the same
  transform; the upload transposes once. See
  [Matrices and 3D math](../../docs/gl.md#matrices-and-3d-math).
- **The math layer needs no context.** `gl.transform` is arithmetic on top of
  `matrix` and `vec`: projections, `Camera`, `Transform`, composition, screen
  space, and picking. Only the `upload`/`set_*` helpers touch the driver, and they
  are no-ops for an inactive uniform name.

## Practical notes

- **Compatibility profile.** The runtime creates a plain WGL context, which
  drivers on Windows serve as a compatibility profile: the immediate-mode calls
  in `gl.immediate` work, and so do `#version 120` shaders. Requesting a core
  profile is not supported by this binding.
- **Row alignment.** An RGBA image whose row length is not a multiple of four
  needs `gl.pixel_store(gl.GL_UNPACK_ALIGNMENT, 1)` before uploading.
- **Queries.** `get_float` and `get_integer` return the first component of a
  query; for ranges and matrices use `floats(pname, count)`,
  `line_width_range()`, `point_size_range()`, or `max_viewport_dims()`.
- **Other hosts.** When `sere_rt` was built without a display layer,
  `gl.available()` is `False`, windows report `is_open() == False`, and the
  enumerants still work, so a program can branch on it and fall back.
